# 模型权重

本目录存放推理用的模型权重。**权重不进版本库**（见根目录 `.gitignore` 的
`models/*.pt`）—— 仅 `jktk_x.pt` 就有 436MB，远超 GitHub 单文件上限。

## jktk_x.pt（当前使用）

| 项 | 值 |
|---|---|
| 架构 | YOLO**11**x |
| 类别数 | 116 |
| 体积 | 436 MB |
| 许可证 | apache-2.0 |
| 来源 | `hf-mirror.com/hodoly163/krishibondhu-jktk` |

### 获取方式

从上述仓库下载 `jktk_x.pt`，放到本目录即可。后端通过
`server/app/config.py` 的 `DEFAULT_WEIGHTS` 定位它；**换权重 = 改这一行**，
API 契约与前端一行不动。

### ⚠️ 这个权重只用来「判型」，不用它「定位」

实测结论（详见 `server/app/services/lesion.py` 的模块 docstring）：

- **判型准** —— 真实照片上 纹枯病 0.947 / 稻瘟病 0.965
- **定位假** —— 它输出的框是 `(0.001, 0.033, 0.997, 0.934)`，**盖住整图约 93%**

原因：这个权重是**图像分类数据集被导出成检测格式**训练的 —— 所谓"框"就是整图。
模型学会了"这张图是什么病"，从未学过"病斑在哪"。116 类里也**没有任何水稻害虫类**，
且存在合并数据集的重复标签。

因此系统的分层架构是：

```
上传图片
  ├─ 第一步  YOLO(jktk_x.pt)  ──► 只取 top-1 类别与置信度，**丢弃它的框**
  └─ 第二步  HSV 图像分割     ──► 找真实病斑位置，逐连通域出框
              └─► build_detections() 把第一步的类别贴到第二步的框上
```

API 响应里用 `localization.method = "lesion-cv"`、`yoloBoxIgnored = "whole-image"`
把这件事**显式透出**，不让"YOLO 精准定位"变成一句虚话。

### 溯源核查

该权重是从外部镜像拉取的 checkpoint，属于**对外部数据的可执行反序列化**，
落盘前经 `tools/scan_checkpoint.py` 静态反汇编核查：36 个调用目标全部是
`torch.*` / `ultralytics.*`，无 `os` / `subprocess` / `socket` / `ctypes` / `exec`。

### 已知残留限制

当病组织与颜色相近的背景**连成一片**时，会被分割层的面积上限
`AREA_MAX_RATIO = 0.25` 整块拒绝（纹枯病样例右侧另有一片病鞘因此未单独出框）。
这是颜色分割的固有边界 —— 也正是真实系统要换成训练好的分割模型的原因。
答辩时建议主动说明。

**若日后拿到病斑级检测数据集，只需替换第二步**（分割层），第一步与整个 API 契约不变。
